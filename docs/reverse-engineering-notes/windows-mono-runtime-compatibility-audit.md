# Windows CLR and Wine Mono compatibility audit

Magicka remains a CLR 2 application on both supported platforms. Windows runs
it on Microsoft's CLR 2 implementation. Linux runs the same managed payload
through Wine and Mono. The Linux desktop installer does not replace the game
runtime or require a separate `Magicka.exe`.

The 0.0.42 through 0.0.45 managed payloads were inspected at each release tag
and at each 0.0.45 executable-changing commit. The audit covered runtime target
versions, assembly references, branch and switch targets, exception-handler
boundaries, and the injected Paradox price-worker delegate.

| Revision | Linux-related change | Managed-runtime result |
| --- | --- | --- |
| 0.0.42 | No Linux desktop package yet. | No unresolved control-flow or forbidden CLR references. |
| 0.0.43 | Native Linux Steam-path discovery and the Wine Mono Paradox-store hang fix. | The new price worker used `System.Action` on a startup path. Windows installations without that later framework type failed in `UpdateParadoxItems`. |
| 0.0.44 | Complete Linux desktop installer package. | Packaging did not change the game runtime. The executable inherited the 0.0.43 delegate failure. |
| 0.0.45 full-collection growth | Grow full `StaticList<T>` and `StaticWeakList<T>` collections without dropping existing entries. | Recompiling five mutation methods replaced the CLR-2 lock call with `Monitor.Enter(object, ref bool)`, which is unavailable before .NET 4. |
| 0.0.45 pool recovery | Construct an Avatar and other supported objects when a reuse pool is empty. | `Avatar.GetFromCache(Player)` retained a `br.s` after its target moved beyond the signed-byte range. Mono ran the method; CLR 2 rejected it. |
| 0.0.45 GC retention | Runtime-specific bounded retention diagnostics. | The instrumentation preserved the already malformed Avatar branch. `PolygonHead.dll` and `Magicka.GcDiagnostics.dll` had no unresolved control-flow or forbidden-reference findings. |

The compatible payload uses `System.Threading.ThreadStart` for the Paradox
price worker, `Monitor.Enter(object)` for collection locks, and a long `br`
for the expanded Avatar cache exit. It retains dynamic collection growth, pool
recovery, and all bounded GC-retention hooks.

After these repairs, the framework-call diff from 0.0.44 contains only
`List<GenericBoss>.Count` and the
`List<WeakReference>(IEnumerable<WeakReference>)` constructor. Both are part of
the CLR-2 API surface. The broader diff from 0.0.42 contains only CLR-2
collection, string-comparison, and file-system APIs.

Release packaging now runs the payload validator before building archives. It
requires all three managed payload assemblies to target CLR 2, rejects CLR 4+
facade references, validates every branch, switch, and exception-handler
boundary, rejects the CLR-4 `Monitor.Enter` overload, verifies the price
worker's `ThreadStart` signature and invocation, and checks the expected GC
lifecycle hooks. The same checks run against a payload regenerated by the
retention instrumenter during development.
